    Frei wählbarer interner Name. Er taucht weder in Sprachantworten noch in Trigger-Erkennung auf.
    deterministic: Die Antwort kommt 1:1 aus dem Template — kein LLM-Aufruf, schnell und kostengünstig. Ideal für feste Auskünfte. llm: Der Agent beantwortet die Anfrage frei, optional mit eigenem System-Prompt und eingeschränkten Tools. hybrid: Das Template sammelt zuerst die Daten, das LLM formuliert daraus eine sprechbare Antwort.
    Je Zeile eine typische Nutzerfrage, z. B. „Wie ist der Hausstatus?". Der Router erkennt auch Abweichungen (siehe Fuzzy-Schwellwert). Ohne Treffer geht die Anfrage an den allgemeinen Agenten.
    0–1, höher = strenger (z. B. 0.95 = fast wörtlich). Leer lassen = globaler Schwellwert aus den Grundeinstellungen. Typisch: 0.8–0.9.
    Gilt nur für llm/hybrid. Leer lassen, um den globalen Agent-Prompt zu verwenden. Der Platzhalter {assistant_name} wird durch den Assistenten-Namen ersetzt. Das Tool-Inventory (agent_inventory) wird weiterhin angehängt.
    Jinja/Nunjucks-Syntax, echte Werte werden vor dem Rendern vorab geladen: {{ ha.state('sensor.temperatur') }} → Zustand einer Entität (HA-Snapshot). {{ ha.entities('light') }} → Liste einer Domain (über das MCP-Such-Tool). {{ ha.call('toolname') }} → ruft ein MCP-Tool ohne Argumente auf; Toolnamen per ➕-Button im Tool-Picker einfügen. {{ shell('befehl') }} → Shell-Befehl im Gateway-Container (Timeout 5 s, Output auf 4000 Zeichen begrenzt). Nur sinnvoll für lokale Skripte/Daten. Auch Nunjucks-Filter und Logik sind verfügbar, z. B. {{ ha.state('x') | round }} oder {% if %}…
    Wirkt nur in den LLM-Modi: das Modell sieht dann ausschließlich die angehakten Facade-/MCP-Tools. Leer = alle erlaubt. Das Template im deterministic-Modus ruft Tools unabhängig davon über ha.call auf.
